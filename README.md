# ForbiddenScan
Консольное приложение .NET 8. Запуск из корня репозитория:
```powershell
dotnet run --project src -c Release -- self-test
dotnet run --project src -c Release -- scan
dotnet run --project src -c Release -- benchmark --iterations 5
dotnet run --project src -c Release -- report --run-dir reports/КАТАЛОГ
```
Параметр scan/benchmark: --input DIR. Каждый запуск автоматически создает reports/yyyy-MM-dd_HH-mm-ss-fff по местному времени запуска. Параметр --run-dir DIR используется только командой report для выбора сохраненного прогона. Алгоритмы: naive, hash, aho, hash-aho.
Входные файлы находятся в InputTerr. Каждый непустой блок нумеруется с 1 в своем файле; строки из пробелов считаются разделителями. Последний блок обрабатывается без завершающего разделителя. UTF-8, BOM поддерживается.

Поиск полного названия после ToUpperInvariant. Пустые названия исключаются, дубликаты удаляются, края названий обрезаются. Внутренние пробелы и пунктуация сохраняются. По обеим сторонам совпадения не должно быть буквы, цифры или подчеркивания. Кавычки и дефисы являются разделителями. Частичные названия, опечатки и синонимы не учитываются. После первого совпадения проверка блока завершается. В matches.log записываются все исходные участники, включая повторы.

naive: последовательный поиск каждой подстроки и проверка границ.
hash: HashSet всех слов из списка отбрасывает строки без общих слов, затем выполняется naive. Названия без слов проверяются отдельно.
aho: бор с суффиксными ссылками, поиск всех шаблонов за проход, проверка границ найденных кандидатов.

Все документы обрабатываются последовательно; в памяти находится текущий блок, структуры шаблонов и идентификаторы найденных блоков. Benchmark выполняет один прогрев каждого алгоритма, затем повторные проходы с циклической сменой порядка. Сравниваются точные последовательности идентификаторов блоков и их общее количество. Время включает чтение, разбор, нормализацию и поиск, но не запись журналов. Кеш файлов прогрет. Перед замерами подготовки каждый вариант создается пять раз для прогрева. Затем новые экземпляры создаются --iterations раз с циклической сменой порядка. Сохраняются все времена подготовки, выводятся минимум, медиана и максимум. Общая загрузка и нормализация списка измеряются отдельно. Это замеры после прогрева; остаточные эффекты JIT и GC возможны. Обычный scan по-прежнему измеряет фактическое однократное создание. Полные блоки записываются отдельным проходом после измерений. Для scan запись блоков тоже вынесена в отдельный проход.

reports/<дата_время>: run.log, matches.log; benchmark дополнительно сохраняет results.json и report.html. HTML можно пересоздать без измерений. Сведения о среде берутся из сохраненных результатов. В терминале только сводка. Требуется SDK .NET 8; BAT и внешние пакеты не используются.

Четыре варианта в общем бенчмарке:
- naive — перебор;
- hash — HashSet слов + перебор;
- aho — Ахо — Корасик;
- hash-aho — тот же HashSet-фильтр + Ахо — Корасик.

Фильтр реализован один раз в HashMatcher и получает основной алгоритм через фабрику.
Для названий без слов создается отдельный matcher того же типа.
Обычная проверка четвертым вариантом:
```powershell
dotnet run --project src -c Release -- scan --algorithm hash-aho
```
Все четыре варианта участвуют в self-test и проверке идентичности результатов бенчмарка.
В режиме scan без --algorithm используется hash-aho (HashSet + Ахо — Корасик).

HTML-отчет содержит условия тестирования, входные файлы, таблицу результатов и ссылки на журналы. Название CPU читается из реестра Windows, физическая ОЗУ — через GlobalMemoryStatusEx; сведения сохраняются в results.json при запуске. Команда report использует сохраненную среду и не подменяет ее характеристиками текущей машины.

Self-test выполняется отдельной командой: .\build\ForbiddenScan.exe self-test. Сборка для запуска по имени: dotnet publish src -c Release -o build.
